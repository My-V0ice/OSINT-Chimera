# OSINT-Химера

Локальный сборник утилит для разных задач: IP, домены, ники, email, телефоны, ФИО и криптоадреса. Слева — инструменты по категориям, в центре — обработанные результаты выбранной утилиты, справа — JSON источника. Каждый инструмент запускается отдельно. История запусков и настройки сохраняются между запусками приложения.

## Запуск в Docker

Нужны Docker Engine с Compose v2 на Linux либо Docker Desktop в режиме Linux containers на Windows. Первоначальная сборка требует интернета и скачивает зависимости открытых инструментов.

Из корня проекта:

```sh
docker compose --profile tools up -d --build
```

Открыть **http://localhost:8000**. Порт опубликован только на локальном компьютере. Встроенной многопользовательской авторизации нет; это персональное локальное приложение.

Скрипты запуска:

```powershell
# Windows PowerShell
.\scripts\start.ps1
# Только основное приложение и прямые адаптеры:
.\scripts\start.ps1 -CoreOnly
```

```sh
# Linux
sh scripts/start.sh
# Только основное приложение:
sh scripts/start.sh --core-only
```

Основное приложение запускается без ключей, GeoLite и контейнеров сборщиков. Недоступные инструменты отображают причину и не отправляют запросов. Для подключения сборщиков позднее выполните полную команду запуска и обновите список через настройки.

```sh
docker compose --profile tools ps
docker compose --profile tools logs --tail 80
docker compose --profile tools down
```

Остановка через `down` сохраняет постоянные тома. Не добавляйте `-v`, если нужны исследования и ключи.

## Ключи и базы

В шапке откройте **Интеграции и ключи**. У IPinfo, AbuseIPDB, Etherscan, TronGrid и OpenAlex можно сохранить, заменить, удалить и явно проверить ключ. OpenAlex допускает базовые запросы без ключа. Сохранение ключа не отправляет сетевой запрос; проверка использует небольшой заранее указанный в коде публичный пример и расходует квоту.

Ключи шифруются Fernet на сервере. База находится в томе `chimera-data`, мастер-ключ — в отдельном `chimera-secrets`. Сохранённые значения не возвращаются браузеру. Для резервного копирования нужны **оба тома**, желательно при остановленном приложении. Доступ к Docker и этим двум томам позволяет расшифровать ключи; шифрование не заменяет защиту локального компьютера.

При работе без Docker данные по умолчанию находятся в `.local/data` и `.local/secrets`. Они исключены из Git и контекста сборки.

Для GeoLite скачайте базы в своём аккаунте MaxMind и распакуйте в папку `geolite`:

```text
geolite/GeoLite2-City.mmdb
geolite/GeoLite2-Country.mmdb
geolite/GeoLite2-ASN.mmdb
```

Можно использовать одну или несколько баз. Обновление баз выполняется пользователем; автоматическая загрузка и загрузка через браузер пока не реализованы. Геолокация IP приблизительна. Lite-версия IPinfo даёт страну и ASN без города и координат. Координаты и радиус точности GeoLite отображаются в данных выбранной утилиты.

AbuseIPDB требует ключ и для вызова через curl. Без ключа автоматическая проверка заблокирована; ручной сайт доступен по ссылке источника. InternetDB бесплатен для некоммерческого использования.

30 адаптеров включают dnspython как отдельный инструмент. Hunter исключён. Фотоинструменты пока не реализованы: их состав не был подтверждён.

Агрегаторы пока используют фиксированные бесключевые наборы. Их ключевые модули отключены до реализации совместного учёта квот и управления конфигурацией. Сохранение ключа прямого адаптера не включает одноимённый модуль SpiderFoot или theHarvester. PhoneInfoga upstream не поддерживается, поэтому интеграция экспериментальная.

Внешние сайты могут менять структуру, блокировать запросы или возвращать CAPTCHA. Установка сборщика и успешный запуск команды не гарантируют работоспособность всех его сайтов. Актуальные внешние данные проверяются на предоставленных пользователем тестовых объектах отдельно.

## Как работать

1. Выберите утилиту в боковой панели. Категории: IP и геолокация, домены и DNS, ники и аккаунты, email, телефоны, ФИО и люди, криптокошельки. Поиск по названию помогает быстро найти инструмент.
2. Введите исходные данные, выберите их тип, если инструмент поддерживает несколько, и нажмите «Запустить». Вызывается только выбранная утилита.
3. В центре отображаются сводка, полученные поля, записи, пояснения и при наличии консольная диагностика. Пустые значения и отрицательные совпадения аккаунтов не создают карточки результата. Числа 0 и значения false сохраняются как реальные данные. Если данных нет, показывается «Ничего не найдено». Ошибки сети, ключа и квоты отображаются отдельно.
4. Справа находится JSON источника, включая пустые поля. Можно скопировать или скачать полный JSON, а также скачать отчёт с метаданными запуска. Большие списки раскрываются порциями через «Показать ещё»; крупный JSON имеет ограниченный предварительный просмотр с полным скачиванием.
5. «История запусков» показывает последние 100 запусков выбранной утилиты, включая старые результаты из предыдущей версии. Выбор записи не вызывает внешних запросов. Старые исследования остаются в локальной базе и доступны через совместимые старые API; основной интерфейс больше не содержит исследований и графа.

ФИО и ники создают кандидатов на совпадение. Приложение не объединяет людей по одному имени. Криптоадреса разделены по сетям; связь с транзакцией не доказывает владельца. Номер телефона проверяется по метаданным, без определения владельца, активности SIM или текущего местоположения.

## Архитектура

- `app/main.py`: локальный HTTP API, интерфейс и защита изменяющих запросов от чужих сайтов.
- `app/catalog.py`: реестр инструментов, поддерживаемые типы, требования и опубликованные лимиты.
- `app/providers.py`: прямые адаптеры, проверка входных объектов, сетевые ошибки и преобразование результатов.
- `app/service.py`: очередь (2 задания одновременно), кэш и состояния; старые функции исследований сохранены для совместимости данных.
- `app/presentation.py`: обработанное представление результата, пропуск отсутствующих значений и различение пустого ответа и ошибки.
- `app/storage.py`: SQLite, квоты и зашифрованные ключи.
- `app/static`: интерфейс без CDN и внешних клиентских библиотек.
- `tools`: отдельные контейнеры с фиксированными командами, без shell-команд пользователя и доступа к Docker socket. Их порты не опубликованы на хосте.

Один процесс приложения совместно учитывает квоты всех своих заданий. Запуск нескольких экземпляров/worker-процессов с одним хранилищем **не поддерживается**. SQLite и встроенная очередь выбраны для первого персонального локального выпуска; очереди Redis и отдельной серверной СУБД сейчас нет.

Для API учитывается каждый исходящий HTTP-запрос, UTC-сутки и интервал между запросами. Остаток показывается только при наличии заголовка источника; локальное число запросов — оценка, потому что ключ может использоваться в других программах. Ошибки HTTP 429 приостанавливают источник; учитывается Retry-After и доступное время сброса. Кэш успешных ответов действует 15 минут, одинаковые одновременные запросы к источнику объединяются. Изменение ключа меняет область кэша.

Задания сохраняются до и после каждого источника. После аварийного перезапуска незавершённые задания отмечаются прерванными; автоматического повторного списания квот нет. Ограничение сборщика — 160 секунд; доступные частичные отчёты сохраняются. Первая страница криптоистории явно отмечается как неполная.

## Локальная разработка и проверки

Python 3.12+; Docker для контейнеров сборщиков:

```sh
python -m venv .venv
# Linux:
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
# Windows:
.venv/Scripts/pip install -r requirements.txt
.venv/Scripts/python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

```sh
.venv/bin/python -m unittest discover -s tests -v
node --check app/static/app.js
node --check app/static/crypto.js
node --check app/static/localcsv.js
node --test tests/ui.test.cjs tests/crypto-ui.test.cjs tests/csv-ui.test.cjs
```

На Windows используйте `.venv/Scripts/python`. Тесты не обращаются к реальным внешним объектам: локальный пример номера из вымышленного диапазона 202-555 и подменённые ответы API. Они проверяют ключи, отсутствие утечек в экспорте, пропуски источников, квоты при параллельных заданиях, кэш, частичные результаты, происхождение данных, валидацию и восстановление прерванных заданий.

Параметры окружения для разработчика: `CHIMERA_DATA`, `CHIMERA_SECRETS`, `CHIMERA_GEOLITE`, `SCANNERS_URL`, `HARVESTER_URL`, `SPIDERFOOT_URL`, `PHONEINFOGA_URL`, `ESPLORA_URL`. Адреса сборщиков и своего Esplora задаются администратором окружения, а не входными данными исследования.

Текущая концепция: [docs/utility-catalog.md](docs/utility-catalog.md). Исходная спецификация [docs/requirements.md](docs/requirements.md) сохранена как история предыдущей концепции. Эта инструкция описывает версию 0.6.

Новые источники поиска аккаунтов, ограничения и проверка: [docs/account-tools.md](docs/account-tools.md).

Правила отображения результатов и новые источники версии 0.5: [docs/output-review.md](docs/output-review.md).

Проверка IP на proxy/VPN через ProxyCheck.io: [docs/proxycheck.md](docs/proxycheck.md).

История и продолжение движения средств: [docs/crypto-transfers.md](docs/crypto-transfers.md). Для Ethereum ETL включите профиль `crypto`, укажите RPC URL в настройках. Для GraphSense нужен готовый сервер и индекс; для Blockscout — отдельный бесплатный ключ.

## Поиск по локальным CSV

В категории «Локальные данные» доступен импорт нескольких CSV и общий поиск по всем полям или выбранному столбцу. Поддерживаются разные схемы, UTF-8/Windows-1251/UTF-16, фоновые индексы, точные и частичные совпадения, телефоны с разным форматированием, страницы результатов и JSON. Данные сохраняются в локальном Docker-томе, без внешних запросов. [Подробная инструкция](docs/local-csv.md).
