# Локальный поиск по CSV

В боковой панели выберите **Локальные данные → Поиск по CSV**.

1. Выберите один или несколько CSV-файлов и нажмите **Импортировать**.
2. Дождитесь статуса **Готов**. Во время фонового импорта приложение остаётся доступным.
3. Отметьте файлы, в которых нужно искать. По умолчанию новые файлы выбраны.
4. Введите телефон, email, ФИО или другое значение. Можно выбрать конкретный столбец и режим **Точное значение**.
5. У найденной записи указаны имя файла и номер начальной физической строки CSV. Раскройте запись для просмотра всех столбцов. Справа — JSON текущей страницы, который можно скопировать или скачать.

## Формат

- Первая строка содержит названия столбцов. Схемы разных файлов могут отличаться.
- Поддерживаются UTF-8 с BOM и без него, Windows-1251 и UTF-16 с BOM; разделители: запятая, точка с запятой, табуляция, вертикальная черта. Автоопределение можно переопределить перед загрузкой.
- Поддерживаются CSV-кавычки, экранированные кавычки, переносы строк в ячейках. Пустые строки пропускаются.
- Повторяющиеся заголовки получают суффикс `_2`, `_3`; пустые — `column_N`. Короткие строки дополняются пустыми ячейками. Строки с лишними столбцами вызывают ошибку импорта всего файла; частичные записи не участвуют в поиске.
- Значения остаются строками: ведущие нули, длинные номера, даты и пустые ячейки сохраняются. Формулы не выполняются, ссылки из CSV автоматически не открываются.
- Символы `�`, уже находящиеся в файле, вызывают предупреждение. Выбор другой кодировки не восстановит текст, если он был потерян до импорта.

## Поиск и хранение

Поиск не учитывает регистр, различия е/ё, повторяющиеся пробелы и оформление номера телефона (`+`, пробелы, скобки и дефисы для числовых значений от 7 цифр). Коды стран и начальные цифры не подменяются: `8…` и `7…` не считаются одним номером автоматически. Исходные значения при этом не меняются.

**Содержит** ищет подстроку. Во всех столбцах допускается поиск по последовательности соседних значений строки, а при выборе столбца — только в его ячейках. **Точное значение** проверяет целую ячейку. Названия столбцов не объединяются по смыслу: например, `phone` и `Телефон` остаются отдельными полями; режим «Все столбцы» ищет в обоих.

Результаты выдаются по 30 записей, с кнопкой следующей страницы. JSON содержит только текущую страницу и параметры запроса; полное количество совпадений не вычисляется. Для быстрого поиска применяется SQLite FTS5 trigram; двухсимвольные запросы могут потребовать просмотра индекса. Ограничение времени поиска — 8 секунд, после него следует уточнить запрос или набор файлов.

Размер одного загружаемого файла — до 512 МиБ. Не больше 256 столбцов, 1 МиБ на ячейку и 2 МиБ текста на строку. Импорт идёт последовательно в фоне; очередь — до 12 файлов. Индекс может занимать в несколько раз больше места, чем исходные CSV.

Индекс находится в `/data/csv/index.sqlite3`, в существующем Docker-томе `chimera-data`, и сохраняется при пересоздании контейнера. В локальном запуске без Docker путь — `.local/data/csv/`. Временная загруженная копия удаляется после импорта, исходный файл на компьютере не меняется. Повторные копии с той же кодировкой и разделителем не индексируются второй раз.

Архив скрывает файл из поиска, сохраняя индекс; **Восстановить** возвращает его в поиск. Это не удаление и не освобождение места. При остановке незавершённый импорт помечается ошибкой; файл можно загрузить снова.

Файлы и запросы не отправляются внешним сервисам, API-ключи не нужны. Индекс хранится локально без шифрования, как результаты прочих утилит. CSV, индексы и временные загрузки исключены из Git и контекста сборки Docker.
