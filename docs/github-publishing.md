# Публикация на GitHub

В проекте уже есть Git и история коммитов. Повторно выполнять `git init` не нужно.
Публикуется исходный код локального приложения; GitHub Pages для FastAPI не подходит.

## Перед загрузкой

- `.local`, `.venv`, ключи, SQLite, CSV и GeoLite исключены из Git.
- Посторонний файл `Томск_вариант_20_восходы_закаты.xlsx` остаётся локально и исключён из Git.
- README содержит запуск, ограничения и инструкции подключения источников.
- `.github/workflows/ci.yml` содержит автоматические проверки.
- Лицензия проекта пока не выбрана. Для выпуска с открытой лицензией владелец должен
  выбрать её и добавить `LICENSE`. Лицензии сторонних инструментов и условия API
  остаются применимыми к соответствующим компонентам.

## Сохранение подготовленных изменений

Из корня проекта проверьте состав загрузки:

```sh
git status --short
git diff --check
git add .gitignore .dockerignore README.md CONTRIBUTING.md .github/workflows/ci.yml docs/github-publishing.md
git diff --cached --stat
git diff --cached
git commit -m "Prepare project for GitHub publication"
```

Если Git просит указать автора, задайте своё имя и email в локальной конфигурации
репозитория (`git config user.name` и `git config user.email`). Для приватности можно
использовать свой GitHub noreply email.

## Создание репозитория и первый push

Создайте **пустой** репозиторий `osint-chimera` в своём аккаунте GitHub. Не добавляйте
README, `.gitignore` и лицензию при создании: исходная история уже содержит файлы проекта.
Выберите нужную видимость репозитория.

Подставьте свой логин вместо `YOUR_USERNAME`:

```sh
git remote add origin https://github.com/YOUR_USERNAME/osint-chimera.git
git push -u origin HEAD
```

Команда сохраняет текущее имя ветки (`master` в исходном репозитории).
Если требуется `main`, перед первым push выполните `git branch -m main`.
Для HTTPS используйте авторизацию через менеджер учётных данных Git или токен
с доступом к репозиторию; не включайте токен в URL и файлы проекта.

Если `origin` уже подключён, сначала проверьте `git remote -v`. Меняйте адрес через
`git remote set-url origin ...` только если это действительно нужный репозиторий.

После загрузки откройте вкладку **Actions** и проверьте все три задания CI.
Локальная подготовка workflow сама по себе не означает успешного запуска в GitHub.

## Последующие изменения

```sh
git status --short
git add <изменённые-файлы>
git diff --cached
git commit -m "Describe the change"
git push
```

Отправка ветки включает её историю. `.gitignore` не убирает файлы из прошлых коммитов.
Если секрет когда-либо был закоммичен, перед публикацией отзовите его и очистите историю.
