# OSINT-Химера — согласованный состав и поведение

Дата: 2026-10-27. Статус: спецификация до реализации и проверки интеграций.

## Назначение

Локальный веб-интерфейс для OSINT-исследований. Основная область: граф связей, таблица результатов, текст и географическое представление. Справа: сведения выбранного объекта, происхождение данных, исходный JSON и история запусков. Основная платформа — Linux с Docker Compose; вторичная — Windows с Docker Desktop/WSL2 и Linux-контейнерами.

SpiderFoot включается в маршрутизацию по всем поддерживаемым и проверенным типам входных объектов, а не только по ФИО. Запуск использует явно выбранные модули и общий учёт провайдеров; неизвестная совместимость модуля отображается в статусе, а не считается реализованной.

## Ключи и первоначальный запуск

- Приложение и база данных запускаются без единого внешнего ключа, регистрации или мастера обязательной настройки.
- Настройки → Интеграции: ввод, замена, удаление ключей и явная проверка подключения. Изменения действуют для следующих заданий без перезапуска контейнеров.
- Обычные ответы сервера содержат только признак наличия ключа и маску. Сохранённое значение нельзя получить через интерфейс обратно.
- Пустое поле при сохранении других настроек не удаляет ключ. Удаление — отдельная операция. Замена с ошибкой проверки не должна незаметно уничтожать прежнюю настройку.
- Переданные пользователем ключи IPinfo, Etherscan и TronGrid предназначены для локальной настройки при реализации. Значения не включаются в спецификацию, исходники, образы, примеры, JSON исследований и логи. Их проверка ещё не выполнялась.
- Хранение: серверное хранилище секретов в отдельном постоянном томе, с шифрованием и локально созданным мастер-ключом вне базы/образа. Для переноса нужен согласованный резервный комплект данных и мастер-ключа.
- Обращения к поставщикам выполняются сервером. Ключи не включаются в клиентские сборки, граф, экспорт и сообщения об ошибках; URL с секретными параметрами очищаются перед журналированием.
- Один поставщик имеет общую конфигурацию и учёт квот для прямого адаптера и поддерживаемых модулей агрегаторов. Синхронизация ключей с конкретной версией агрегатора проверяется при реализации; неподдерживаемый модуль остаётся недоступным.

## Доступность и ошибки

Состояния: готов, требуется ключ, требуется база/настройка, отключён, выполняется, завершён, частичный результат, неверный ключ, лимит исчерпан, ошибка источника.

Отсутствие обязательного ключа блокирует только соответствующую интеграцию или модуль. В карточке доступны объяснение и переход к настройкам. Сервер также запрещает запуск такого модуля, не отправляя внешний запрос. Общий поиск продолжает работать с доступными источниками.

У theHarvester, PhoneInfoga и SpiderFoot пропускаются только модули с невыполненными условиями. Причины пропуска видны в истории задания. Если не осталось доступных модулей, запуск недоступен. Локальные проверки номера доступны независимо от внешних сканеров.

Ошибка сети, таймаут, CAPTCHA, неверный ключ и HTTP 429 не превращаются в «не найдено». При истощении квоты работа источника приостанавливается до сброса; Retry-After учитывается, повторные попытки ограничены.

## Квоты и способы работы

В карточке показываются: место выполнения, внешний источник, протокол, необходимость ключа, условия бесплатного использования, опубликованные лимиты, дата их проверки, известный остаток и сброс. Неизвестный остаток явно обозначается неизвестным. Локальный счётчик показывается как оценка: ключ может использоваться вне приложения.

curl — HTTP-клиент, а не способ отменить API-авторизацию. Документированный AbuseIPDB check требует заголовок Key и при вызове curl. Для AbuseIPDB без ключа предусматривается ссылка на ручную проверку сайта; её содержимое не выдаётся за полученный приложением JSON. Автоматический парсинг публичной страницы не считается подтверждённой интеграцией.

Лимиты задаются конфигурацией по провайдеру, endpoint и временному окну; соблюдаются всеми обработчиками совместно. Кэш и дедупликация предотвращают повторное списание за идентичные запросы, когда это допускают свежесть и условия источника. Платное расширение не включается автоматически.

## Данные и граф

Хранятся исходный ответ, нормализованные сущности и утверждения/связи с источником, временем запроса, временем данных при наличии, версией адаптера и ссылкой на доказательство. Не-JSON вывод сохраняется отдельно и оборачивается адаптером в JSON с явным указанием преобразования.

Повторное обнаружение объекта добавляет источник, а не стирает прежние данные. Противоречия видны отдельно. Совпадение ФИО или ника не объединяет людей автоматически. Криптоадрес хранится с сетью; привязка владельца требует самостоятельного доказательства. Геолокация IP приблизительная; регион телефонного номера не означает текущее местоположение.

## Критерии приёмки

1. Чистый запуск без ключей открывает интерфейс; доступные локальные и бесключевые проверки работают.
2. Недоступный модуль показывает конкретное недостающее условие; его запуск через сервер также блокируется.
3. Ввод, замена и удаление ключа меняют доступность без перезапуска; значения сохраняются после пересоздания контейнера с прежними томами.
4. Массовый поиск выполняет доступные модули и перечисляет пропуски, сохраняя частичные результаты.
5. Ключи отсутствуют в клиентских ресурсах, обычных ответах, экспортах и логах, включая ошибки поставщиков.
6. Общая квота соблюдается при параллельных заданиях и обращениях через агрегаторы.
7. Для выбранного узла показаны сведения, источники, исходный JSON и состояние задания.
8. Конкретные версии всех 18 интеграций проверяются отдельно; установленный, настроенный и проверенный инструмент различаются в интерфейсе.
