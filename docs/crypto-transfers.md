# Перемещение средств — версия 0.6.1

В категории «Криптокошельки» добавлены Blockscout Transfers, GraphSense и Ethereum ETL. Esplora и TronGrid расширены режимом истории переводов. Всего в каталоге 30 утилит. Граф не используется: в центре таблица, справа исходные страницы ответов JSON, в истории — каждый самостоятельный запуск и его параметры.

## Работа в интерфейсе

1. Выберите Esplora для BTC, TronGrid для TRON, Blockscout для EVM. Укажите адрес. Для EVM доступны Ethereum, Base, Optimism и Scroll (поддержка конкретных методов зависит от сервиса).
2. Выберите операции, число страниц (1–3), направление, актив/контракт, суммы и период. Для TronGrid — обычные TRX или TRC-20; для Blockscout — монеты, токены или внутренние операции.
3. Нажмите «Запустить». Суммы хранятся десятичными строками без преобразования в JavaScript float. Неизвестные decimals не угадываются: отображаются атомарные единицы. Фильтры относятся только к загруженным страницам. Разные активы не суммируются.
4. «Загрузить следующие страницы» продолжает историю с курсора источника и сохраняет параметры. Это отдельный запуск, предыдущие страницы остаются в истории. Пустая страница после фильтров не означает отсутствия переводов в остальной истории.
5. Нажатие на адрес открывает его историю в той же утилите и сети. Автоматический обход адресов не выполняется. В текущем интерфейсе ограничение — 6 ручных переходов до нового поиска. Путь переходов хранится только в открытой вкладке; каждый запрос доступен в общей истории.

Таблица показывает отправителей, получателей, сумму/актив, время, тип операции и TXID. Неуспешные операции помечаются, если источник предоставил статус. Отсутствие статуса не подтверждает успешное выполнение. Сведения о контрагентах не устанавливают владельца адреса.

## Bitcoin / Esplora

[Esplora API](https://github.com/Blockstream/esplora/blob/master/API.md) — открытый проект, публичный сервер без ключа либо собственный `ESPLORA_URL`. Используются подтверждённые страницы `/address/{address}/txs/chain/{last_seen_txid}`, по 25 транзакций на страницу. На запуск до 3 страниц и до 5 запросов `/tx/{txid}/outspends` (по умолчанию 2). Непроверенные расходования не обозначаются как непотраченные.

Каждый выход транзакции — отдельная запись. Если адрес участвовал во входах, показываются выходы общей транзакции без приписывания всех средств конкретному входу. Сдача на другие адреса не определяется автоматически. Coinbase с `prevout=null` поддерживается. Для потраченного выхода показана расходующая транзакция: действие по получателю с этим TXID загружает следующую транзакцию и её выходы. Неадресные выходы остаются без кнопки перехода.

## TRON / TronGrid

Используется существующий ключ TronGrid. Обычные TRX берутся из `/transactions`, только `TransferContract`; переводы через другие контракты и внутренние операции в этом режиме не реконструируются. TRC-20 — `/transactions/trc20`. Адреса hex конвертируются в Base58Check; суммы TRX делятся на 10^6, суммы токенов — на предоставленные источником decimals. Пагинация использует `fingerprint`; URL следующей страницы из ответа не запрашивается напрямую.

Актуальные [квоты TronGrid](https://developers.tron.network/reference/rate-limits) зависят от аккаунта и методов. Фиксированная локальная квота 100 000 убрана, ограничения сервиса учитываются через ответы API. Статус подтверждения и полнота данных зависят от источника.

## Blockscout Transfers

Нужен отдельный бесплатный ключ из [Developer Portal](https://dev.blockscout.com/). Вводится в общих настройках. [Free](https://docs.blockscout.com/devs/blockscout-api): 100 000 кредитов/сутки, 5 запросов/с. Кредиты не равны числу HTTP-вызовов. Используется Universal API `https://api.blockscout.com/v2/api` с `chain_id` и действиями `txlist`, `tokentx`, `txlistinternal`, по 50 записей на страницу. В приложении интервал 0,25 с. Старые per-instance ключи не подходят.

## GraphSense

Адаптер подключается к уже работающему [GraphSense REST API](https://graphsense.org/documentation). Система без этого подключения продолжает работать. В настройках укажите URL API, доступный из Docker (например `http://host.docker.internal:9000`), при необходимости отдельно API-ключ. Сохранённый URL зашифрован и не возвращается в поля браузера. Пустой URL удаляет подключение. URL с логином/паролем и схемы, отличные от HTTP(S), не принимаются.

Маршрут: `/{currency}/addresses/{address}/txs`, валюты BTC/ETH/TRX при наличии индекса, `pagesize=50`, курсор `page`. Адаптер ориентирован на схему GraphSense REST `address_txs`/`next_page`. Для UTXO показано изменение баланса адреса, без выдуманных получателей и отправителей. Токены с неизвестными decimals остаются в атомарных единицах.

Полный индексатор GraphSense, Cassandra и копии блокчейнов автоматически не устанавливаются: они требуют отдельного сервера и подготовленных данных. Коммерческая облачная услуга Iknaio не считается бесплатным локальным компонентом.

## Ethereum ETL

Добавлен отдельный приватный Docker-сервис `ethereumetl`, профиль `crypto`, с CLI `ethereum-etl==2.4.2` и изолированным Python 3.10. Запуск: `docker compose --profile tools --profile crypto up -d --build`. Для настроенного окружения с готовыми образами достаточно `--no-build`.

В настройках укажите HTTP(S) URL собственного RPC или RPC-провайдера. Если ключ входит в URL, адрес хранится целиком зашифрованным. Из браузера он не читается. В контейнере адрес `localhost` относится к самому контейнеру; для сервиса Windows/Linux-хоста обычно нужен соответствующий доступный сетевой адрес.

На Linux имя `host.docker.internal` при необходимости задаётся через `extra_hosts: ["host.docker.internal:host-gateway"]` в локальном Compose override для `app` и `ethereumetl`; также можно использовать доступный IP хоста или имя сервиса в общей Docker-сети. Docker Desktop обычно предоставляет это имя автоматически.

Выберите сеть, начальный и конечный блок: включительно от 1 до 20 блоков за запуск. Сборщик проверяет `eth_chainId`, затем запускает фиксированную команду экспорта монет, токенов либо Parity-style traces, максимум 1 поток и 120 секунд. В таблицу/JSON возвращаются только операции указанного адреса. Команды подписи и отправки транзакций отсутствуют. Для токенов CLI не предоставляет decimals: сумма сохраняется в атомарных единицах. Нативный экспорт без receipts не подтверждает успешность исполнения транзакций.

CLI-логи не возвращаются, чтобы URL с RPC-ключом не оказался в истории. Временные CSV ограничены 4 МБ и удаляются. Доступность трассировок и их стоимость определяются вашим RPC; бесплатная CLI не даёт бесплатного доступа к архивному узлу. Старые зависимости Ethereum ETL изолированы от основного приложения.

## Совместимость и проверки

Существующие API и исторические ответы сохранены. Новый интерфейс передаёт `options` в `/api/tools/{tool}/runs`; опции входят в ключ кэша. Параметры проверяются до постановки задания. Смена ключа или URL увеличивает ревизию и исключает использование старого кэша. Сырые ответы страниц остаются в JSON; нормализованные переводы доступны в полном отчёте.

Проверки покрывают точность сумм, multi-input BTC, расходования, coinbase, пагинацию, запрет URL вместо курсора BTC, фильтры, неизвестные decimals, TRX Base58Check, ошибки и частичные ответы, шифрование URL и ключ кэша с учётом сети. Тесты интерфейса проверяют экранирование, пустые страницы, переход по адресу и расходующей транзакции. Реальные пользовательские адреса в автоматических тестах не используются.

Прошли 89 серверных и 8 тестов интерфейса. Сборщик Ethereum ETL собран и запущен: CLI 2.4.2 проверена реальными экспортами native/token/internal на изолированном HTTP RPC с пустым тестовым блоком. Все три режима завершились без ошибки; RPC получал только читающие запросы и временные фильтры логов. Пользовательский RPC не использовался.

В браузере проверена реальная история публичного демонстрационного BTC-адреса `1BoatSLRHtKNngkdXEeobR76b53LETtpyT`: 25 записей на первой странице, ручной переход по адресу, следующие 25 записей по курсору, исходный JSON справа и настольная трёхколоночная компоновка. Внешний Blockstream API сначала отвечал нестабильно (таймаут/ошибка сети), после восстановления запросы завершились успешно. Ошибки не маскировались под отсутствие переводов. Blockscout ожидает отдельного ключа; GraphSense — готового сервера/индекса; живые запросы к ним и к пользовательскому TronGrid в этой проверке не выполнялись.

Обнаруженный при визуальной проверке конфликт поля фильтра `token` с защитой API-токенов устранён: используется `asset_filter`. Отдельный регрессионный тест проверяет сохранение публичного фильтра без подмены маркером скрытого секрета. Изображение: [crypto-preview.jpg](crypto-preview.jpg).
