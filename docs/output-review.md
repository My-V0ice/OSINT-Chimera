# Обработка результатов и новые инструменты — 2 ноября 2026

## Исправления

Проверены структуры сохранённых ответов 17 использованных источников без вывода значений запросов и ключей. Обнаружен воспроизводимый случай theHarvester: `result_count=0`, пустые `artifacts`, `hosts`, `shodan`, но непустые `cmd` и служебная summary-запись ошибочно считались данными. Теперь центральная панель извлекает только email, домены, хосты и IP из структурированных находок; команды, цели, таймстампы и счётчики не являются находками. Поддерживаются прежний JSON и новые JSONL artifacts.

В Maigret статус вложен в объект `status`. Рекурсивная обработка могла посчитать одну находку дважды — профиль и вложенный URL. Общие правила для сервера и сборщиков теперь требуют явного положительного статуса, останавливаются на отрицательном статусе и исключают конфигурацию сайтов. Sherlock с отрицательным/неопределённым `exists` не считается найденным профилем. У Holehe регистрация учитывается только без ошибки и rate limit, включая ранее сохранённые ответы. В SpiderFoot исключаются исходные события `SpiderFoot UI` и пустые события; WHOIS и другие непустые наблюдения модулей сохраняются.

Ошибка разбора, неизвестный статус и ограничения в структурированных отчётах превращают отображение в неполный результат, даже если старый запуск был записан как завершённый. Статус в интерфейсе берётся из актуальной обработки. Новый запуск использует те же правила в контейнере. Исходные ответы и исторические записи не переписываются: исправление применяется при просмотре. Диагностика остаётся отдельно от находок и доступна в JSON. Ноль жалоб, отрицательный признак Tor и нулевой баланс являются результатами проверки и не скрываются как «пустота». PhoneInfoga по-прежнему разделяет локальные метаданные и непроверенные поисковые ссылки.

## Новые инструменты

| Инструмент | Вход / результат | Режим / доступ |
|---|---|---|
| [Keybase](https://github.com/keybase/client) | Точный ник Keybase или домен; публичный профиль и опубликованные связи | [HTTPS API](https://keybase.io/docs/api/1.0/call/user/lookup), без ключа; гарантированная квота не опубликована; интервал 1 секунда |
| [EmailRep](https://github.com/sublime-security/emailrep.io) | Репутация email, свойства домена и признаки профилей | Внешний API с открытой спецификацией/клиентами; база сервиса не поставляется локально. [Бесплатный Community-ключ](https://emailrep.io/key): 250/месяц и до 10/сутки |
| [PyWhat](https://github.com/bee-san/pyWhat) 5.1.0 | Определение возможного формата строки: email, кошелёк, хеш и другие идентификаторы | Локально, без квот и ключей, до 254 символов; отдельное окружение в `accounts` |

Всего 26 инструментов. PyWhat расположен в категории «Идентификаторы». Он анализирует только введённую строку (`only_text=True`), не читает файлы и не проверяет найденные ключи через сеть. Это классификация, а не поиск владельца. Примеры и шаблоны из справочника PyWhat остаются только в JSON; в центре показывается совпавшая строка и возможный тип. Версия PyWhat зафиксирована; её зависимости изолированы от сервера.

Keybase показывает доказательства связей по данным сервера, без независимой криптографической верификации. EmailRep не возвращает гарантированный список аккаунтов: оценки, ссылки на источники репутации и названия платформ рассматриваются как сведения сервиса, а не установленная принадлежность. Без ключа EmailRep недоступен, приложение продолжает работать. Ключ вводится, заменяется и удаляется в обычной панели настроек.

## Проверки

64 серверных теста и 5 тестов интерфейса проходят, включая сохранённые формы пустого theHarvester, вложенный Maigret, seed SpiderFoot, parse error, rate limit, сохранение 0/false, пустой Keybase и PyWhat, авторизацию EmailRep и публичные связи Keybase. Тесты не запрашивают данные пользователей во внешних сервисах.

В работающем приложении повторно обработаны сохранённые ответы: пустой theHarvester стал `empty`, профиль Maigret учитывается один раз, содержательные WHOIS/DNS-события SpiderFoot сохраняются. На вымышленном нике публичный Keybase API вернул HTTP 200 и ноль результатов. PyWhat установлен в отдельном окружении, команда прошла стартовую проверку и полный вызов через `/api/tools/pywhat/runs`: тестовая строка `example@example.org` распознана как email, исходный JSON доступен. Реальный EmailRep не вызывался: требуется пользовательский ключ. Подключение к браузеру недоступно, визуальная проверка этой версии не выполнена; отображение проверено автоматическими тестами.

Существующие образы обновлены поверх установленных зависимостей. Из-за недоступности PyPI из Docker колёса PyWhat скачаны с официального PyPI через хост и установлены в контейнер без сети. Обычные Dockerfile проекта содержат установку из PyPI для последующих сборок в среде с доступом к нему; чистая сборка всех базовых образов в этой сессии не завершалась. Секреты и базы остаются в прежних томах.
